# Joomla → WordPress announcements migrator

Scripts for migrating the announcements of a Joomla site to WordPress **without admin access to Joomla**. Everything is collected from the public RSS feed of the announcements category, so no database dump or back-end login is needed.

Written for `https://vo.duth.gr/index.php/el/anakoinoseis`, but it should work with any Joomla site whose category feed is enabled.

## How it works

1. `scrape.py` pages through the Joomla RSS feed (`?format=feed&type=rss&start=N`), collects every announcement (title, date, slug, HTML content) and writes them to `announcements.csv`. It also extracts all links to attached files and images and saves them to `files.txt`.
2. `download.py` downloads every file listed in `files.txt`, keeping the original folder structure.
3. `rewrite.py` points the links inside the announcements to the new location of the files and writes `announcements_new.csv`, the file to import into WordPress. It also prints a short report of things that need a manual decision.
4. `wayback.py` (optional) looks up files that returned 404 in the Internet Archive.
5. `casefix.py` (optional) handles files whose URLs differ only in letter case.

## Repository layout

| Path | Description |
|---|---|
| `scrape.py` | Reads the feed and generates `announcements.csv` and `files.txt`. |
| `download.py` | Downloads all attachments listed in `files.txt` into `downloads/`. Skips files that already exist. |
| `rewrite.py` | Rewrites file links and generates `announcements_new.csv` plus a report. |
| `wayback.py` | Optional. Checks whether files listed in `failed.txt` exist in the Wayback Machine. |
| `casefix.py` | Optional. Finds URLs that differ only in letter case, downloads both variants and compares their content. |
| `announcements.csv` | *Generated.* One row per announcement with the original links. |
| `announcements_new.csv` | *Generated.* Same rows with rewritten links. This is the file to import. |
| `files.txt` | *Generated.* One attachment URL per line. |
| `downloads/` | *Generated.* Downloaded attachments, e.g. `downloads/images/...`. |
| `failed.txt` | *Generated.* Files that could not be downloaded (URL and error), usually 404s. |
| `downloads_case/` | *Generated by `casefix.py`.* Both variants of every case-conflicting file, in folders `1/` and `2/`. |
| `.gitignore` | Excludes generated data and downloaded files from version control. |

## Requirements

- Python 3.9+
- `requests` and `beautifulsoup4`

```bash
pip install requests beautifulsoup4
```

On Windows, if `pip` is not recognised, use `python -m pip install requests beautifulsoup4`.

## Usage

Run the steps in this order from the project folder.

### 1. Generate the CSV and the file list

```bash
python scrape.py
```

Progress is printed while the feed is paged through (`fetched 16`, `fetched 32`, …). At the end you get a summary such as `939 announcements, N files`.

To migrate a different category or site, change the `FEED` constant at the top of `scrape.py`.

### 2. Download the attachments

```bash
python download.py
```

Files are saved under `downloads/`, mirroring the paths used on the old site. The script can be re-run safely: existing files are skipped and only missing ones are retried. Failed downloads are written to `failed.txt`.

### 3. Check files that failed (optional)

Old announcements often link to files that were deleted from the server (HTTP 404). To see whether the Internet Archive has a copy:

```bash
python wayback.py
```

If a copy exists, download it manually and place it in `downloads/` under the same path. Otherwise decide whether to remove the link from the announcement or keep it with a note that the file is no longer available.

### 4. Rewrite the links

Edit the two constants at the top of `rewrite.py`:

```python
OLD_PREFIX = "https://vo.duth.gr/images/"
NEW_PREFIX = "https://NEW-SITE/wp-content/uploads/vo-archive/images/"
```

Then run:

```bash
python rewrite.py
```

The script writes `announcements_new.csv` and prints:

- how many announcements contain embedded `<img>` tags,
- links to the old site that are *not* under `/images/` (old pages, `tel:` links, etc.),
- announcements that link to files that failed to download.

It also repairs `tel:` links that the feed turned into `https://old-site/tel:...`.

## CSV format

| Column | Meaning |
|---|---|
| `title` | Announcement title. |
| `old_slug` | Original Joomla slug, kept for building redirects. |
| `slug` | Slug for WordPress, truncated to 200 characters (the WordPress limit). |
| `date` | Original publication date, `YYYY-MM-DD HH:MM:SS`, in the server's local time. |
| `content` | Cleaned HTML body (inline classes, ids, empty links and `download`/`target` attributes removed). |

The files are UTF-8 with BOM, so Greek text opens correctly in Excel.

## Checks before uploading the files (Windows / PowerShell)

Run these from the project folder before uploading `downloads/images/` to the server.

### 1. Files with non-ASCII (e.g. Greek) names

```powershell
Get-ChildItem downloads -Recurse -File | Where-Object { $_.Name -match '[^\x00-\x7F]' } | Select-Object FullName
```

The built-in Windows zip (`Compress-Archive`) stores such names with an encoding that many Linux servers and hosting panels (e.g. Plesk) cannot read, which leaves broken file names and 404s. If this lists any files, **do not upload a zip**. Upload the folder directly over SFTP (FileZilla, WinSCP) instead.

### 2. Names that differ only in letter case

```powershell
Get-Content files.txt | ForEach-Object { [uri]::UnescapeDataString($_).ToLower() } | Group-Object | Where-Object Count -gt 1
```

Windows treats `File.pdf` and `file.pdf` as the same file, while the Joomla server and the new Linux server do not. When two URLs differ only in case, `download.py` keeps the first one and skips the second one, because the file "already exists". Any pair listed here must be checked manually: download both variants, compare them, and make sure both exact names exist on the server so that every link keeps working.

`casefix.py` automates this check:

```bash
python casefix.py
```

For every pair of URLs that differ only in case, it downloads both variants into `downloads_case/1/` and `downloads_case/2/` (same folder structure as `downloads/`) and prints a short hash of each, followed by one of:

- `ΙΔΙΟ ΠΕΡΙΕΧΟΜΕΝΟ` (same content): both names just need to exist on the server.
- `ΔΙΑΦΟΡΕΤΙΚΟ` (different content): each announcement must point to its own file, so keep both variants under their exact names.
- `HTTP 404` for one variant: the link to that variant was already broken on the old site.

Upload the variants missing from `downloads/` (via SFTP) so that both exact names exist on the Linux server.

### 3. File types about to be uploaded

```powershell
Get-ChildItem downloads -Recurse -File | Group-Object Extension | Select-Object Name, Count
```

Expect only documents and images (`.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.jpg`, `.png`, …). There should be no `.php`, `.html` or executable files, because these files are copied straight to the server without any WordPress upload checks.

## Importing into WordPress

1. **Upload the attachments.** The simplest option is to upload the `downloads/images/` folder to the new site, for example to `wp-content/uploads/vo-archive/images/`, via FTP or the hosting panel. Make sure this matches `NEW_PREFIX`.
2. **Import `announcements_new.csv`** with a plugin such as **WP All Import**, mapping:
   - `title` → Title
   - `content` → Content
   - `date` → Date
   - `slug` → Slug / Post name
   - a fixed category (e.g. "Announcements")
3. **Redirects.** Use `old_slug` to map old URLs of the form `/index.php/el/anakoinoseis/<old_slug>` to the new posts (for example with the Redirection plugin or an `.htaccess` rule).
4. **Manual fixes.** Replace links to old Joomla pages that were reported by `rewrite.py` with their new equivalents.

## Notes and limitations

- The feed returns 15–16 items per request. The scraper advances by the number of items received and stops at the first empty page.
- Links are collected from `href` and `src` attributes pointing to the old site's `/images/` folder. Files hosted elsewhere (Google Forms, eClass, other websites) are left untouched.
- Only the announcements category is covered. Other categories have their own feed URLs.
- The scripts wait between requests (1 s for the feed, 0.5 s for downloads) to be polite to the server.
- Some old attachments may no longer exist on the server. Check `failed.txt` after downloading.
- Downloaded files and generated CSVs are not committed to the repository (see `.gitignore`).
